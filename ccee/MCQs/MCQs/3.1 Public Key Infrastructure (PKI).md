### **2. Theory Summary**

#### **Information Security**

- **Definition:** The practice of protecting data from unauthorised access, use, disclosure, disruption, modification, or destruction.
- **Goals:** Known as the CIA Triad:
    - **Confidentiality:** Ensuring data is accessible only to authorised users.
    - **Integrity:** Maintaining the accuracy and completeness of data.
    - **Availability:** Ensuring that information and resources are accessible when needed.

#### **Security Attacks & Threats**

- **Types of Security Attacks:**
    
    - **Passive Attacks:** Observing or monitoring data without altering it (e.g., eavesdropping).
    - **Active Attacks:** Modifying or disrupting data and systems (e.g., tampering, DoS).
- **Common Threats:**
    
    - **Phishing:** Deceptive techniques to obtain sensitive information.
    - **Malware:** Malicious software, such as viruses, worms, and ransomware.
    - **Denial of Service (DoS):** Overloading systems to disrupt services.
    - **Man-in-the-Middle (MitM):** Intercepting communication between two parties.
- **Mitigation Strategies:**
    
    - Strong passwords and authentication methods.
    - Regular system updates and patches.
    - Network security measures like firewalls and intrusion detection systems.

### **2. Theory Summary**

#### **Cryptographic Fundamentals**

- **Definition:** Cryptography is the science of securing data and communication by converting it into an unreadable format for unauthorised users.
- **Core Objectives:** Confidentiality, Integrity, Authentication, and Non-repudiation.

#### **Cryptographic Ciphers**

- **Types of Ciphers:**
    - **Symmetric Ciphers:** Use the same key for encryption and decryption (e.g., DES, AES, RC5).
    - **Asymmetric Ciphers:** Use a pair of keys – public and private keys (e.g., RSA, ECC).
    - **Substitution Ciphers:** Replace characters with other characters (e.g., Caesar cipher).
    - **Block vs. Stream Ciphers:** Block ciphers encrypt data in fixed-size blocks, while stream ciphers encrypt data bit by bit.

#### **Protocols in Cryptography**

- **Definition:** Protocols define the rules and methods for secure communication.
- **Examples:**
    - **HTTPS:** Secure web communication by encrypting HTTP data.
    - **TLS/SSL:** Secure transmission of data over networks.
- **Key Generation:**
    - Generates cryptographic keys for securing data.
    - Keys must be random, unique, and robust to ensure security.

### **2. Theory Summary**

#### **Symmetric Key Encryption**

- **Definition:** Uses a single key for both encryption and decryption.
- **Examples:** DES, AES, RC5.
- **Key Features:**
    - Faster encryption and decryption.
    - Requires secure key distribution to all parties.

#### **Algorithms:**

- **DES:**
    - Key Length: 56 bits.
    - Vulnerability: Susceptible to brute-force attacks.
- **AES:**
    - Key Lengths: 128, 192, or 256 bits.
    - Widely used for secure communication.
- **RC5:**
    - Highly customisable with variable block sizes, key sizes, and number of rounds.

#### **Asymmetric Key Encryption**

- **Definition:** Uses a pair of keys – a public key for encryption and a private key for decryption.
- **Examples:** RSA, ECC.
- **Key Features:**
    - Eliminates the need for secure key sharing.
    - Slower compared to symmetric encryption but more secure.

#### **Algorithms:**

- **RSA:**
    - Based on the mathematical difficulty of factoring large prime numbers.
    - Commonly used for secure data transmission and digital signatures.
- **ECC (Elliptic Curve Cryptography):**
    - Provides equivalent security to RSA with smaller key sizes, making it efficient for mobile devices.

### **2. Theory Summary**

#### **Diffie-Hellman Key Exchange**

- **Purpose:** Allows two parties to securely share a secret key over an insecure channel.
- **How It Works:**
    - Both parties agree on a shared base and prime number.
    - Each party generates a private key and computes a public key.
    - Public keys are exchanged, and each party calculates the shared secret using the private key and the other’s public key.
- **Vulnerability:** Susceptible to Man-in-the-Middle attacks without authentication.

#### **Cryptographic Issues**

- **Key Challenges:**
    
    - Weak key management (e.g., storing keys insecurely).
    - Use of outdated or weak algorithms (e.g., DES).
    - Human factors, such as poor password policies.
- **Common Attacks:**
    
    - Cryptanalysis: Exploiting weaknesses in algorithms.
    - Man-in-the-Middle: Intercepting and altering communication.
    - Brute Force: Attempting all possible keys.
- **Mitigation Strategies:**
    
    - Regularly update encryption protocols.
    - Implement strong key management policies.
    - Use modern, secure algorithms (e.g., AES, ECC).
