### **DevOps Last-Minute Revision Chart**

| **Topic**                        | **Key Concepts & Tools**                                                                                                                                                                  | **Notes/Definition**                                                                                                                                                                                                                                                                                                                                                           |
|-----------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Virtualization**                | Virtualization types: Type 1 (bare-metal), Type 2 (hosted)                                                                                                                                  | Virtualization allows the creation of virtual versions of physical resources (servers, storage, etc.). Type 1 runs directly on hardware; Type 2 runs on a host operating system.                                                                                                                                                                                             |
| **Containers**                    | Docker, Kubernetes, Docker Compose, Container Orchestration                                                                                                                                  | Docker creates isolated containers, Kubernetes manages containerized applications. Compose helps define and run multi-container Docker apps.                                                                                                                                                                           |
| **Cloud Computing**               | IaaS, PaaS, SaaS, Public/Private/Hybrid Cloud                                                                                                                                               | IaaS: Infrastructure as a Service, PaaS: Platform as a Service, SaaS: Software as a Service. Public: shared resources, Private: dedicated resources, Hybrid: combination.                                                                                                                                                                                                   |
| **CI/CD**                         | Jenkins, Git, GitHub, GitLab, Jenkinsfile, Webhooks, CI/CD Pipelines                                                                                                                        | CI/CD automates integration and deployment. Jenkins integrates with Git to automate testing, building, and deployment. Pipelines describe the stages of code delivery.                                                                                                                                                                                                       |
| **Infrastructure as Code (IaC)**  | Terraform, Ansible, CloudFormation                                                                                                                                                          | IaC allows infrastructure provisioning through code. Terraform is multi-cloud, Ansible automates configurations, CloudFormation is AWS-specific.                                                                                                                                                                                                                             |
| **Monitoring & Logging**          | Prometheus, Grafana, ELK Stack (Elasticsearch, Logstash, Kibana), AWS CloudWatch, Nagios, Grafana                                                                                           | Prometheus collects metrics, Grafana visualizes them. ELK stack handles log aggregation and visualization. CloudWatch monitors AWS resources. Nagios is an open-source monitoring system.                                                                                                                                                                                      |
| **Automation**                    | Ansible Playbooks, Terraform, Chef/Puppet                                                                                                                                                  | Automation tools configure and deploy resources. Ansible uses Playbooks (YAML-based), Terraform uses configuration files for IaC, Chef and Puppet use code to automate infrastructure tasks.                                                                                                                                                                                     |
| **Cloud Services**                | AWS (EC2, S3, Lambda, VPC, RDS), Azure, Google Cloud                                                                                                                                         | AWS EC2 runs virtual servers, Lambda provides serverless functions, S3 stores data, VPC creates a private network. Google Cloud and Azure offer similar services.                                                                                                                                                                                                          |
| **Microservices**                 | Kubernetes, Docker Swarm, AWS ECS, Docker Compose                                                                                                                                          | Microservices are small, independent services that communicate over a network. Kubernetes and Docker Swarm are orchestration tools for managing these services. ECS (Elastic Container Service) on AWS is for managing Docker containers.                                                                                                                                          |
| **High Availability (HA)**        | Load Balancing, Auto Scaling, Multi-AZ, Multi-Region                                                                                                                                       | HA ensures the application is always available. Load balancing distributes traffic, Auto Scaling adjusts the number of servers based on load, Multi-AZ and Multi-Region improve fault tolerance.                                                                                                                                                                               |
| **Disaster Recovery (DR)**        | Backups, Multi-AZ, Multi-Region, S3 Glacier, CloudFormation                                                                                                                                 | DR ensures services can recover from failure. Multi-AZ and Multi-Region setups help replicate data across regions. S3 Glacier is cost-effective long-term storage.                                                                                                                                                                                                           |
| **Version Control**               | Git, GitHub, GitLab, Git Workflow (clone, commit, push, pull)                                                                                                                                | Git is a version control system. GitHub and GitLab host repositories. Git workflow involves cloning repos, committing changes, and pushing/pulling to/from remote repositories.                                                                                                                                                                                             |
| **Security & IAM**                | IAM, VPC Security Groups, Key Management Services (KMS), AWS WAF, VPN                                                                                                                     | IAM (Identity and Access Management) controls access. VPC Security Groups act as firewalls. KMS manages encryption keys. AWS WAF is a web application firewall, VPN secures network connections.                                                                                                                                                                           |
| **Container Orchestration**       | Kubernetes, Docker Swarm, Helm                                                                                                                                                             | Kubernetes is the leading container orchestrator. Helm is a package manager for Kubernetes, enabling the deployment of applications. Docker Swarm is Docker’s own orchestration tool.                                                                                                                                                                                         |
| **Continuous Integration**        | Jenkins, GitHub Actions, Travis CI, CircleCI                                                                                                                                               | CI tools automatically build and test code after commits, ensuring continuous integration and reducing bugs. Jenkins is the most widely used, GitHub Actions integrates with GitHub.                                                                                                                                                                                            |
| **Continuous Deployment**         | Jenkins, Spinnaker, AWS CodePipeline, Kubernetes                                                                                                                                           | CD automates code deployment after successful integration. Jenkins, Spinnaker, and AWS CodePipeline are commonly used tools for continuous deployment. Kubernetes supports automated deployments.                                                                                                                                                                              |
| **Network Configuration**         | VPC, Subnets, Route Tables, VPN, Load Balancers                                                                                                                                           | VPC (Virtual Private Cloud) enables network configuration in the cloud. Subnets, route tables, and VPNs manage traffic, while Load Balancers distribute incoming traffic.                                                                                                                                                                                                  |
| **Serverless**                    | AWS Lambda, Azure Functions, Google Cloud Functions                                                                                                                                       | Serverless allows you to run code without managing servers. AWS Lambda, Azure Functions, and Google Cloud Functions allow functions to be triggered by events.                                                                                                                                                                                                              |
| **Infrastructure Monitoring**     | AWS CloudWatch, Prometheus, Grafana                                                                                                                                                        | CloudWatch monitors AWS resources and custom metrics. Prometheus collects metrics from cloud resources, and Grafana visualizes the data for actionable insights.                                                                                                                                                                                                              |
| **Cloud Architectures**           | Single-Region vs Multi-Region, Auto Scaling, Load Balancers                                                                                                                                | Single-Region architecture operates in one region; Multi-Region architecture operates across multiple regions for failover and redundancy. Auto Scaling and Load Balancers help ensure elasticity and traffic distribution.                                                                                                                                                        |
| **Containerization Best Practices**| Immutable Containers, Multi-Stage Builds, Resource Limits, Health Checks                                                                                                                   | Immutable containers never change once deployed. Multi-stage builds optimize Docker images. Resource limits and health checks ensure that containers run efficiently and reliably.                                                                                                                                                                                             |
| **DevOps Culture**                | Collaboration, Continuous Feedback, Automation, Monitoring                                                                                                                                 | DevOps emphasizes collaboration between development and operations. Continuous feedback, automation of testing and deployment, and monitoring ensure a fast and reliable delivery pipeline.                                                                                                                                                                                    |
| **Agile & Scrum**                 | Scrum, Kanban, Sprint Planning, Stand-ups                                                                                                                                                 | Agile methodologies like Scrum and Kanban promote iterative development. Scrum involves sprints (time-boxed iterations), stand-ups (daily meetings), and continuous delivery.                                                                                                                                                                                                |
| **Deployment Strategies**         | Blue-Green, Canary, Rolling Updates                                                                                                                                                      | Blue-Green deployment involves two environments: one live and one staging. Canary deployment releases changes to a small subset of users, while Rolling Updates gradually replace old versions with new ones.                                                                                                                                                                    |

### **Additional Quick Tips for DevOps Engineer Role:**

- **Automation**: Ensure automation of testing, deployment, and scaling to reduce human errors and improve consistency.
- **CI/CD Pipeline Optimization**: Optimize the pipeline for speed while maintaining code quality.
- **Version Control Best Practices**: Use branching strategies (e.g., GitFlow) to streamline collaboration and deployment.
- **Security**: Regularly audit access controls, keys, and permissions (IAM roles, policies).
- **Scalability & Availability**: Always design systems with scalability and high availability in mind. Use load balancers and auto-scaling to handle traffic spikes.

### **Terraform Last-Minute Revision Chart**

| **Topic**                         | **Key Points**                                                                                              | **Example/Command** |
|------------------------------------|------------------------------------------------------------------------------------------------------------|---------------------|
| **Terraform Overview**             | Infrastructure as Code (IaC) tool to automate provisioning of cloud resources. Supports multiple providers. | -                   |
| **Providers**                      | Configures cloud providers (AWS, Azure, Google Cloud, etc.). Use provider block to define cloud platform.   | `provider "aws" { region = "us-west-2" }` |
| **Resources**                      | Define infrastructure resources (e.g., EC2, VPC, S3). Resource blocks are used to create resources.        | `resource "aws_instance" "example" { ami = "ami-123456" instance_type = "t2.micro" }` |
| **Variables**                      | Allows dynamic values (e.g., region, instance type) for flexibility.                                      | `variable "region" { type = string default = "us-west-2" }` |
| **Outputs**                        | Define output values to expose resource attributes.                                                        | `output "instance_id" { value = aws_instance.example.id }` |
| **State Management**               | Tracks the state of resources. Important for Terraform to manage and update infrastructure.                  | `terraform state list` <br> `terraform state show aws_instance.example` |
| **Terraform Init**                 | Initializes Terraform working directory. Downloads provider plugins.                                        | `terraform init` |
| **Terraform Plan**                 | Shows the changes Terraform will make based on the configuration.                                           | `terraform plan` |
| **Terraform Apply**                | Applies the changes and provisions the resources.                                                           | `terraform apply` |
| **Terraform Destroy**              | Destroys all managed infrastructure as defined in the configuration.                                         | `terraform destroy` |
| **Terraform Modules**              | Reusable configurations for common infrastructure setups. Can be used across projects.                     | `module "vpc" { source = "./modules/vpc" cidr_block = "10.0.0.0/16" }` |
| **Remote State**                   | Stores state files remotely (e.g., AWS S3) for collaboration and security.                                 | `backend "s3" { bucket = "my-tf-state" key = "terraform.tfstate" region = "us-west-2" }` |
| **Terraform Workspaces**           | Allows managing multiple environments (e.g., dev, prod) with different configurations.                      | `terraform workspace new dev` <br> `terraform workspace select dev` |
| **Terraform Provider Aliases**     | Multiple configurations for the same provider (e.g., different regions).                                    | `provider "aws" { alias = "west" region = "us-west-2" }` |
| **Terraform Functions**            | Built-in functions for dynamic values (e.g., `join()`, `lookup()`, `length()`).                              | `join(",", var.tags)` |
| **Terraform Loops**                | Use `for_each` and `count` for dynamic creation of multiple resources.                                       | `resource "aws_instance" "web" { count = 3 ami = "ami-123" instance_type = "t2.micro" }` |
| **Terraform Provisioners**         | Executes scripts or commands on provisioned resources. Useful for post-creation configuration.               | `provisioner "remote-exec" { inline = ["sudo apt-get update"] }` |
| **Terraform Import**               | Imports existing infrastructure into Terraform management.                                                   | `terraform import aws_instance.example i-12345678` |
| **Error Handling**                 | Terraform error handling (e.g., resource conflicts, variable issues).                                         | Review error logs and debug using `terraform validate` |
| **Terraform Best Practices**       | - Use modules for reuse <br> - Version control state <br> - Avoid hardcoding values <br> - Use remote state | - |
| **CI/CD Integration**              | Automate Terraform in pipelines (e.g., Jenkins) using `terraform init`, `plan`, and `apply`.                | Jenkins pipeline example: `sh 'terraform apply -auto-approve'` |
| **Cross-Provider Setup**           | Define multiple providers (e.g., AWS and Azure) in a single config file.                                   | `provider "aws" { region = "us-west-2" }` <br> `provider "azurerm" { features = {} }` |
| **Terraform Security**             | Use AWS IAM, secrets management for sensitive data like access keys.                                         | `AWS_ACCESS_KEY_ID = credentials('aws-access-key-id')` |

### **Essential Terraform Commands**

| **Command**                        | **Description**                                              |
|------------------------------------|--------------------------------------------------------------|
| `terraform init`                   | Initialize Terraform configuration and download provider plugins. |
| `terraform validate`               | Validate the configuration files for syntax and logical errors. |
| `terraform plan`                   | Create an execution plan, showing the actions Terraform will take. |
| `terraform apply`                  | Apply the changes and provision resources defined in the configuration. |
| `terraform destroy`                | Destroy all the resources created by Terraform.              |
| `terraform output`                 | Show output values defined in Terraform configuration.       |
| `terraform state list`             | List all the resources in the current Terraform state.       |
| `terraform state show`             | Show detailed state of a specific resource.                  |
| `terraform import`                 | Import an existing resource into Terraform management.       |
| `terraform workspace new <name>`   | Create a new workspace for different environments.            |
| `terraform workspace select <name>`| Select the current workspace.                               |

### **Key Best Practices**

| **Best Practice**                      | **Description**                                          |
|----------------------------------------|----------------------------------------------------------|
| **Use Version Control**                | Store `.tf` files and `terraform.tfstate` files in version control (e.g., Git). |
| **Manage State Remotely**              | Use remote backends like AWS S3 for Terraform state to enable collaboration and avoid conflicts. |
| **Modularize Configurations**          | Use reusable modules to promote DRY (Don't Repeat Yourself) principle. |
| **Handle Secrets Securely**            | Use secure methods (e.g., AWS Secrets Manager) for sensitive data instead of hardcoding values. |
| **Use Workspaces for Environments**    | Use different workspaces for environments like `dev`, `staging`, `prod` to isolate configurations. |
| **Review Changes Before Apply**        | Always run `terraform plan` to review changes before applying them in production. |
| **Maintain Infrastructure as Code**    | Store infrastructure configurations in version-controlled repositories for auditing and easy recovery. |
| **Use Variables for Dynamic Inputs**   | Avoid hardcoding values; use variables for better flexibility and environment-specific configurations. |
| **State Locking**                      | Enable state locking (e.g., with DynamoDB for AWS) to prevent concurrent operations on the same state file. |
