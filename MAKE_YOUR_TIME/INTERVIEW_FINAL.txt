5. How do you set up a DNS on a Linux server? What are the types of records in DNS? What are zones in DNS?
	1. Install BIND
		sudo apt update
		sudo apt install bind9 bind9utils bind9-doc
	2. Configure the main file
		Edit /etc/bind/named.conf to include your zone files.
			include "/etc/bind/named.conf.local";
	3. Define zones
		In /etc/bind/named.conf.local, define your forward and reverse zones:
			zone "example.com" {
				type master;
				file "/etc/bind/zones/db.example.com";
			};
			zone "1.168.192.in-addr.arpa" {
				type master;
				file "/etc/bind/zones/db.192";
			};
	4. Create zone files
		Create the /etc/bind/zones/db.example.com file (forward zone):
			$TTL 604800
			@   IN  SOA ns1.example.com. admin.example.com. (
					1     ; Serial
					604800 ; Refresh
					86400  ; Retry
					2419200; Expire
					604800 ); Negative Cache TTL
			;
			@       IN  NS      ns1.example.com.
			ns1     IN  A       192.168.1.10
			www     IN  A       192.168.1.20
	5. Restart BIND
		sudo systemctl restart bind9
	6. Test DNS
		dig @localhost example.com

what is NAC in networking
	NAC in networking stands for Network Access Control. It's a security solution that controls which devices are allowed to connect to a network, 
	enforcing policies to ensure that only authorized and compliant devices gain access.
		Key Functions of NAC:
			Authentication – Verifies the identity of users and devices before granting access.
			Authorization – Grants different levels of access based on user roles, device type, location, etc.
			Compliance Enforcement – Ensures devices meet security policies (e.g., antivirus, OS version) before access is allowed.
	How NAC Works:
		A device tries to connect to the network (wired, wireless, or VPN).
		NAC checks the device's identity and security posture.
		Based on the policy:
			The device is allowed full access.
			Given limited access (e.g., internet only).
			Denied or quarantined.

What is VPC
	VPC stands for Virtual Private Cloud.
	In cloud computing (especially on platforms like AWS, GCP, or Azure), a VPC is a logically isolated network environment 
	within a public cloud where you can launch and manage cloud resources like virtual machines (VMs), databases, containers, etc., in a secure, private way.
	
	What You Can Do With a VPC:
		Feature	Description
		Subnets ->	Divide your VPC into smaller networks (public/private)
		Routing tables ->	Control traffic flow within and outside the VPC
		Security groups	->  Act like firewalls to control inbound/outbound traffic
		Internet Gateway ->	Allow public internet access to resources in public subnets
		NAT Gateway	->	Allow private resources to access the internet without being exposed
		VPC Peering ->	Connect two VPCs securely (within or across accounts)
		VPN / Direct Connect ->	Securely connect on-premises network to your VPC
	
	Why VPC Is Important:
		Isolation:- No other customers can see your traffic or resources.
		Security:- Fine-grained control over who can access what.
		Flexibility:- You define the network topology, firewall rules, and connectivity.
		Scalability:- Easily expand across regions and subnets.

What is default network
	Default network refers to the default route or default gateway that a device uses when it doesn't know how to reach a particular destination.
		Default Gateway: It's the IP address of a router that connects the local network to other networks, including the internet.
		Devices send traffic to the default gateway when there's no specific route for the destination IP in their routing table.
		Example:
			If a computer wants to send data to 8.8.8.8 but only knows how to reach its local network, it will forward that data to the default gateway.

What is docker network
	A Docker network is a way to enable communication between Docker containers and between containers and the outside world (like your host or the internet).
	Docker networks allow containers to discover and communicate with each other securely and efficiently.
	
	Types of Docker Networks
	1. Bridge (default)
		Use case: Containers on a single host.
		docker run -d --name myapp --network bridge nginx
	2. Host
		Use case: Maximum performance, but no network isolation.
		docker run --network host nginx
	3. None
		Use case: You don’t want the container to have any network.
		docker run --network none nginx
	4. Overlay
		Use case: Multi-host Docker Swarm setups.
		docker network create -d overlay my_overlay

What is Subnet and why it is important
	What is a Subnet?
		A subnet (short for subnetwork) is a smaller network created by dividing a larger IP network into multiple, smaller, more manageable pieces.
	
	Why is subnetting important?
		Improved Network Management:
			Helps organize devices logically.
			Easier to manage groups of devices (e.g., separate subnets for departments).

		Better Performance:
			Limits broadcast traffic within a subnet.
			Reduces network congestion.

		Enhanced Security:
			You can isolate subnets to control traffic between them.
			Helps limit the spread of network attacks.

		Efficient IP Address Use:
			Helps avoid wasting IP addresses.
			You can create subnets of different sizes tailored to the number of devices.

What is Availability zone
	An Availability Zone (AZ) is a geographically separate data center or group of data centers within a cloud provider’s region designed to provide high availability and fault tolerance.
	What is an Availability Zone?
		Cloud providers like AWS, Azure, Google Cloud split their regions into multiple Availability Zones.
		Each AZ is isolated from failures in other zones (e.g., power outages, natural disasters).
		They are connected by fast, low-latency networks so resources can replicate or communicate quickly between zones.
	
	Why are Availability Zones important?
		High Availability:
			By deploying applications across multiple AZs, if one AZ goes down, others keep running.
			Helps avoid single points of failure.

		Fault Isolation:
			Problems in one AZ (like hardware failure or network issues) don’t affect others.

		Disaster Recovery:
			Data and applications can be replicated between AZs to ensure quick recovery.

		Scalability:
			Resources can be spread across AZs for load balancing and better performance.

		Gather information: What exactly is not working? Error messages? Logs?

		Look at logs from the system, app, or network devices.

		Use tools like kubectl logs, docker logs, system logs, or cloud provider dashboards.
	4. Isolate the Cause
	5. Test Possible Solutions
		Apply fixes one at a time and check the results.
		For example:
			Restart the service/container.

			Update config files.
			Rollback recent changes.

	7. Document Findings
		Write down what you found, what you did, and the outcome.

How docker build happens
	docker build is the command that takes a Dockerfile and creates a Docker image from it.
	
	Step-by-step process:
		Dockerfile is read line-by-line:
			The Docker daemon reads your Dockerfile instructions from top to bottom.

		Each instruction creates a new image layer:
			Docker images are made up of layers.
			For each command (like FROM, RUN, COPY), Docker executes the instruction and creates a new layer on top of the previous one.
			Layers help with caching and reusing unchanged parts.

		Docker uses a cache if possible:
			If Docker has already built an image with the same steps and inputs before, it will reuse cached layers instead of rebuilding them.
			This speeds up builds significantly.

		Commands are executed in the build context:
			The build context is the folder you specify when running docker build (usually the current directory .).
			Files copied into the image (via COPY or ADD) come from this context.

		At the end, Docker creates a new image:
			After running all instructions, Docker bundles all layers into a new image.
			This image can be run as a container.

Host vs bridge network
	Bridge Network
		Default Docker network mode (when you don’t specify one).
		Creates a private internal network on the Docker host.
		Containers get their own private IP addresses inside this network.
		Containers communicate with each other using these IPs or container names.
		Containers are isolated from the host network by default.
		External access to containers requires port mapping (-p or -P flag).
		Useful for when you want network isolation between containers and the host.
		docker run -d --name web --network bridge -p 8080:80 nginx
	Host Network
		Containers share the host’s network stack directly.
		No network isolation — container uses host’s IP and ports.
		No port mapping needed; container listens directly on the host’s network interfaces.
		Provides better performance (no network translation overhead).
		Useful for applications that require high performance or need to access host network services directly.
		Less secure because containers can access host network resources freely.
		docker run -d --network host nginx

What is aws lambda
	AWS Lambda is a serverless compute service provided by Amazon Web Services that lets you run your code without provisioning or managing servers.
	
	How AWS Lambda works:
		You write a function.
